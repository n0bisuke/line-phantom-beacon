# 応用コンテンツ: 感度とキャリブレーションの「どこをどう変えるとどうなるか」

ESPectre を**ハンズオン(分かりやすい反応重視)**から**常設運用(外出推定・睡眠記録)**まで使い分けるための実践ガイド。
数値のプリセットは**実験用の仮設定**(公式の用途別推奨値ではない)です。現場で必ずログと照らしながら調整します。

⚠️ 実装状況(重要): この文書の「しきい値系調整」(`threshold` / `motion_on_hits` / `motion_off_hits` /
High-Accuracy 切替)は、**本プロジェクトでは未実装**(ソース上は可能。`docs/espectre-feature-survey.md` 参照)。
現時点で secrets.h だけですぐに変えられるのは**疑似イベントの秒しきい値(10/20/30秒)**のみ。
検知器側の調整は、以下を理解した上での将来実装です。

---

## 1. まず全体像: 2階建ての調整

```
[第1層] 検知器の感度      → threshold / motion_on_hits / motion_off_hits (ESPectre)
        どのくらいの「電波の乱れ」を動きと判定するか
[第2層] イベントの時間判定 → PSEUDO_LEAVE_MS / PSEUDO_CONTINUED_MS / PSEUDO_SLEEP_MS (secrets.h)
        検知した動きから「10種20種30種の通知」を作るロジック
```

用途別の使い分け:

| 用途 | 第1層(検知器感度) | 第2層(時間しきい値) |
|---|---|---|
| ハンズオン(分かりやすさ優先) | **高め**(手振りで即反応) | 10/20/30秒のまま |
| 部屋の活動検知(標準) | 標準 | 10/20/30秒 |
| 外出・帰宅の推定 | **低め**(小さな動きに反応しない) | **長く**(例: 30分で「不在の可能性」) |
| 睡眠中の大きな動きの記録 | **低め**(寝返り中心) | 継続通知はオフ寄り |

注意: 感度を下げても「外出中」「睡眠中」の**確定判定**はできません。「動きがない=不在/睡眠」ではない
(本プロジェクトの疑似イベント設計と同じ思想)。

---

## 2. 第1層: 検知器の3項目(将来実装)

| 設定 | 意味 | 変えたときの効果 |
|---|---|---|
| `threshold`(0〜1の動き確率) | このスコアを超えたら動きの候補 | **上げる=鈍感**(小さな動きを無視)。下げる=高感度(誤検知も増える) |
| `motion_on_hits` | 何回連続でしきい値超えたら motion 判定 | **増やす=チャタリング無視**(瞬間的なノイズを跳ねる)。減らす=即応性アップ |
| `motion_off_hits` | 何回連続で下回ったら静止判定 | **増やす=動いた時間が長く続く**(MOVE表示・presence=1 の持ち時間が伸びる) |

**プリセットの実験値**(例。必ず現場で調整):

| プリセット | threshold | on_hits | off_hits | 挙動イメージ |
|---|---|---|---|---|
| ハンズオン高感度 | 0.4 | 2 | 1 | 手振り・一歩で即反応。誤検知も出る |
| 標準 | 0.5 | 3〜5 | 2〜3 | 普段の動きを安定検知 |
| 低感度(外出/睡眠) | 0.7 | 8 | 3 | 歩行級のみ反応。寝返りはほぼ無視 |

- `threshold` は**High-Accuracy モードでなければ意味が薄い**: Lightweight は起動キャリブレーションで
  自動調整され、設定値はキャリブ完了前の窓にしか効かない。**固定値で比較実験するなら High-Accuracy**
  (`PHANTOM_ALGO_HIGH_ACCURACY` — 実装済みのスイッチを後から有効化する形、`docs/espectre-feature-survey.md` 参照)
- Lightweight のしきい値を変えたければ、**キャリブレーション時の環境(静かさ・人の有無)**を変えるのが
  正攻法(自動調整されるため)

## 3. 第2層: secrets.h で今すぐ変えられるもの

```c
#define PSEUDO_LEAVE_MS      10000UL  // 「動きがなくなりました」を出すまでの秒数
#define PSEUDO_CONTINUED_MS  20000UL  // 「継続して動きがありません」
#define SLEEP_SUSPECTED_MS   30000UL  // 「寝落ちの可能性」(これ以降 push しない)
```

- **外出推定の実験**なら例えば `300000UL`(5分)〜 `1800000UL`(30分)に引き上げ:
  「長時間無動作=不在の可能性」のタイムラインを Grafana presence で見られる
- 睡眠実験なら leave 系を長く(寝返りで即通知されるのを防ぐ: presence は残るので
  Grafana の event 数で観察し、push は最小限に)
- 文言の「(10秒無動作・擬似)」の秒数は**自動で追従**します

## 4. 多人数・複数台での同時運用

| 台数 | CSI トラフィック目安 | 懸念 |
|---|---|---|
| 1台 | 100pps(既定) | 問題なし |
| 3台 | 300pps | 余裕あり |
| 5台 | 500pps | AP 負荷を確認 |
| 10台 | 1,000pps | Wi-Fi 競合に注意 |
| 20台 | 2,000pps | 取得率低下の可能性(50pps への引き下げを検討) |

- **各 ESP32 は独立に検知し、結果は自動統合されない**
- **同じ部屋・同じ動きでも、台ごとに検知結果が異なる**ことがある(位置・アンテナ・反射経路が違うため)
  — ハンズオンではむしろ教材(「どこに置くか」の話題になる)
- **CSI occupancy の目安は 70% 以上**: 複数台で occ が落ちたら pps を下げるか台数/配置を変える
- 各自テザリングを使うとトラフィックが分散して有利だが、
  「観測領域=自分のスマホとESP32の間」になる点に注意(スマホを ESP32 の近くに置きすぎない)

## 5. 無人時に反応した場合の調査フロー(実例: 外出時間帯に event が記録された)

Grafana の telemetry を回すと「不在のはずの時間帯に event/presence が立つ」ことがあります
(実際に 1 件確認済み)。この時:

1. **感度を変える前に CSI 健康 を確認**: `occ` が 70% 以上か / `admitted_pps` が 100 前後か / RSSI
   - occ が不安定なら High-Accuracy 化や感度調整では根本解決にならない(Wi-Fi 環境の問題)
2. **物理的に動くものを疑う**: エアコン・扇風機・カーテン・ペット・扉の開閉(反射経路が変わる)
3. **隣室・廊下の人の動き**: CSI は電波経路全域を拾う(別文書 `docs/espectre-feature-survey.md` も参照)
4. **温湿度**: 研究上は CSI が環境変化でゆっくり変わることが知られているが、遅い変化は検知アルゴリズムが
   無視しやすい。まず疑うのは 1〜3
5. グラフ上の「event 数」は **1人の動きが複数回カウントされる**ことがあり、人数を直接表さない

## 6. チートシート: 変える場所と効果の早見表

| 変えたいこと | 変える場所 | 変更方法 |
|---|---|---|
| 部屋の活動通知のタイミング | `include/secrets.h` | `PSEUDO_LEAVE_MS` 等(今すぐ可) |
| 外出/睡眠のような長時間判定 | 同上 | leave 系のしきい値を長く(Grafana presence で確認) |
| 検知器の感度・安定性 | ESPectre 設定(env フラグ /将来実装) | `docs/espectre-feature-survey.md` の3項目 |
| キャリブレーションの手間を無くす | 同上 | High-Accuracy への切替(同上) |
| 複数台で occ が落ちる | env トラフィック/配置 | pps を下げる(要実装)/台数分散/テザリング分散 |
